## 最小人工复核包（一条修正即可）

私下保存，不提交原始对话、接口响应或个人信息到仓库：

1. 旧记忆与候选新记忆的原文、各自来源会话及时间；同一事实键与完整作用域。
2. 一份可回查的原始变更记录、接口响应或配置快照；标明采集时间、版本、环境、保管位置和 SHA-256。整理后的 Wiki 页只能作线索。
3. 明确的生效时间、查询时间；区分“已生效”“计划/草案”“无法判断”。
4. 非提出该修正的人复核原始材料，记录复核人、时间、`verified_current` / `draft` / `contradicted` / `uncertain` 判定及一句证据依据。无法独立复核时留空或记 `uncertain`，不能由助手代填。
5. 记录复核所花分钟数；与写入、召回、完整问答延迟和实际费用分开统计。

## 实验准入与停止条件

- 仅 `verified_current` 且原始材料、版本、作用域、生效时间均能核对时，才进入 **报告层**重排试跑；`draft`、`contradicted`、`uncertain` 或材料缺失时保持原排序。
- SHA-256 只检出材料在提交后是否改动，不证明作者、来源或事实真实。现有 `correction_journey_probe.py` 是固定订单超时合成用例，不能直接代表 CNCA 案例或任意事实键。
- 一例只能检查流程能否执行；要考虑生产默认，仍需独立留出会话上的最终回答正确率、过时/有害回答率，以及完整用户时间和费用的对照结果。
- 原有 96 行相关性盲标继续暂停；本试点不填写或替代那份标注。
